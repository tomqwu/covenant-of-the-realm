# 《山河有契》单机剧情 RPG 基础设计 v0.1

状态：已确认方向，垂直切片实施前的架构合同
引擎：Godot 4.7.1
内容边界：原创修仙世界；参考作品只提供类型层面的研究启发

## 1. 产品判断

《山河有契》的下一阶段是一款中文优先、单人、章节式、2D 俯视角修仙剧情
RPG。玩家在城镇、山野、宗门与秘境之间探索，通过对话、调查、资源准备、
回合战斗与境界突破推进固定主线。

现有 Evennia MUD 与 Journey PWA 都保留为可运行的研究原型。它们分别验证了
多人权威规则和浏览器叙事可访问性，但不再定义新 RPG 的客户端架构。

## 2. 设计支柱

1. **谨慎胜于刷级。** 情报、准备、退路和资源取舍比重复战斗更重要。
2. **境界改变规则。** 突破带来新的行动、风险和社会关系，而不是只增加数值。
3. **旅伴属于篇章。** 同伴因共同目标加入，也会在目标结束后离队；傀儡、灵兽
   与法宝可以填补战术位置，但不能替代人物关系。
4. **地图承担叙事。** 城镇、道路、洞府和秘境通过空间、机关与资源讲述世界，
   不把所有信息塞进对话框。
5. **失败可以继续。** 撤退、受伤、资源损失和任务分支优先于无条件死亡读档。
6. **固定主线，有限分支。** 主线保持可制作、可测试；支线、资源和关系反馈可变。

## 3. 核心循环

```text
据点整备
  → 交谈与调查
    → 地图探索 / 迷宫
      → 战前准备
        → 回合战斗或撤退
          → 战后抉择
            → 关系与境界变化
              → 返回据点
```

短循环是一次调查、采集或战斗，目标时长 3–8 分钟。中循环是一个地区任务，
目标时长 30–60 分钟。长循环是一章完整的矛盾与境界门槛，目标时长 3–5 小时。

## 4. 战斗合同

垂直切片采用三个战术位置：主角、篇章同伴、部署物。部署物可以是傀儡、灵兽
或持续生效的法宝。每回合先选择行动，再按速度与效果结算。

首个灰盒只实现主角行动与同伴被动支援，以验证以下规则：

- 普通术式稳定但效率有限；
- 符箓伤害高且数量有限；
- 防御降低当回合伤害并创造恢复节奏；
- 敌我数值与结算完全确定；
- 胜利后不能继续领取战斗收益；
- 非法或过期行动不会改变状态。

后续加入五类行动：术式、法宝、消耗品、阵位、撤退。属性相克不会采用单一的
五行剪刀石头布，而由环境、材质、状态和情报共同决定。

## 5. 修炼合同

境界不是传统角色等级的别名。一次突破至少需要：

- 足够但有上限的灵气积累；
- 身体或经脉条件；
- 一项知识、地点或仪式条件；
- 可识别的失败风险；
- 完成后新增的能力和世界反馈。

首个切片只覆盖 `凡身 → 引息境一层`。达到目标后当地修炼收益停止，避免原型
数值被误解为无限成长系统。

## 6. 剧本与内容模型

内容按 `篇 → 章 → 节点 → 行动 → 可能目标` 组织。节点类型限定为：

- `explore`：地图探索和环境互动；
- `dialogue`：人物交流；
- `battle`：确定性战斗；
- `cultivation`：修炼与突破；
- `ending`：章节收束。

每份剧情文件必须声明 `origin: original`。内容检查会拒绝未知字段结构、断开的
目标、不可达节点、没有结局的故事，以及从起点无法完成的图。展示文本与规则
代码分离；规则返回语义事件，客户端再从内容文件取得中文文本。

长篇结构不能逐章搬运。类型研究只抽取资源稀缺、信息差、地理升级、组织交换和
境界风险等抽象原则。任何外部作品的人物、地名、专有物品、原文或独特情节组合
都不得进入内容文件。

## 7. 技术架构

```text
rpg/
├── content/       原创剧情图与本地化展示文本
├── src/domain/    与画面无关的确定性规则
├── src/ui/        Godot 场景、地图和交互界面
└── tests/         无窗口规则测试与场景冒烟测试

scripts/
├── check_rpg_content.py  剧情图静态检查
├── godot                固定的引擎入口
└── setup_rpg            CI/Linux 的校验下载
```

首版使用 GDScript 与 Godot Resource/JSON，不引入网络服务、运行时 LLM、ECS、
行为树或第二套脚本语言。Python 只用于构建期内容验证。存档最终采用版本化快照和
语义事件摘要；不得序列化场景树或任意脚本对象。

## 8. 90 分钟垂直切片

切片暂沿用项目已原创建立的照禾县区域，但会从命令式房间重做为图形地图：

1. 照禾渡口：移动、交谈、任务与整备；
2. 月芽田：地图采集与一次不可重复的资源选择；
3. 藏泉山道：机关、敌人预警与撤退教学；
4. 藏泉石室：首领战、同伴支援与首次引息；
5. 渡口余波：人物反馈、图鉴和章节结算。

目标内容量：1 个据点、2 个野外/迷宫地图、1 位篇章同伴、3 类普通敌人、
1 个首领、6–8 个支线交互、1 次境界突破。

## 9. 质量门禁

- 所有规则路径有无窗口单元测试；
- 剧情图节点和引用完整性为 100%；
- 从新游戏到章节结算有自动化端到端路径；
- 非法行动、重复奖励、存档版本和资源缺失有回归测试；
- 新规则的语句和分支覆盖率目标不低于 99%；
- 键盘、鼠标和手柄共享同一语义行动；
- 简体中文为首发文本，布局必须允许未来繁体中文和英文；
- 所有外部字体、图像、声音和插件在引入前记录来源与许可证。

## 10. 决策边界

垂直切片暂以 PC/macOS/Linux 为开发目标，这是实施假设而非发行承诺。主机、
移动端、商业模式、正式美术方向和完整配音均需在切片验证后单独决定。

如果未来取得外部小说 IP 的正式改编权，应在独立内容仓库和法律审查流程中建立
授权素材管线；不能把当前公开仓库自动视为获准改编的生产环境。
