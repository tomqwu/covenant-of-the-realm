# 《山河有契》下一阶段生产计划 v0.1

状态：明早可玩切片之后的实施候选，尚未承诺发行平台或正式资产预算
基线：Godot 4.7.1；`codex/rpg-foundation` 已具备短章节闭环、存档、输入与包验证
目标：先把当前 3–8 分钟功能切片扩成 15–20 分钟生产质量样章，再扩至 90 分钟

## 1. 当前基线

当前构建已经可以从中文标题页完成以下路径：

```text
砚青简报 → 自由移动与碰撞 → 月芽田采集 → 藏泉山门
  → 可撤退确定性战斗 → 同伴援护 / 石灯部署
    → 藏泉石室听泉辨脉 → 月芽温脉 → 静坐引息
      → 章节结算 → 返回标题 / 继续 / 重游
```

工程证据包括 152 项 pytest（600 statements / 306 branches，均为 100%）、2,716 项
Godot 规则/场景断言、330 项完整章节 E2E、169 项原始鼠标/键盘/手柄输入与焦点断言，
以及存档 v1–v15 到当前 v16 的迁移。save v16 不新增字段，只为四段可恢复巡路端点
对话扩展合法 ID；settings v4 独立保存标准/快速/整句对话显字。Godot 4.7.1 导出时关闭
文本场景二进制转换，门禁把当前 checkout 的两次导出与两个独立空导入缓存的项目副本
逐字节比较。四个本地 macOS/arm64 PCK 均为 709,100 bytes，SHA-256 为
`e8308c22cda27e45b73fcf35e4fbb37587a266ead18d7be5c277c0864d74d351`；manifest v2 另记录
规范化构建元组，但元组不是 canonical hash 键，托管与跨 OS 等同性只接受同源受控证据。
包门禁要求 22 项运行资源、排除 9 项开发资源。两轮连续 41 张 PNG 的聚合 SHA-256 均为
`6e1c0f5b3bca174f25726bfec6de61c86bb9962e57641ca29de90717dc68f4b7`。
现阶段最大缺口不再是底层闭环，而是正式人物精修、探索密度和内容时长。

## 2. 官方资料核对后的技术路线

1. **地图使用多个 `TileMapLayer`，不采用已弃用的单体 `TileMap`。** 地表、遮挡、
   装饰和碰撞分别成层，减少排序与批量更新耦合。Godot 官方说明 `TileMapLayer`
   每节点承载单层 TileSet 数据，多个节点组合成地图。
2. **人物使用 `AnimatedSprite2D` + `SpriteFrames`。** 第一套生产规格为四方向待机/
   行走，保持 56 px 人物高度；开启 2D 变换和顶点像素对齐，避免半像素变形。
3. **玩家碰撞继续由确定性地图规则负责。** `TileSet` 碰撞用于编辑器可视化和运行
   时复核，但不能形成第二套互相矛盾的任务/交互规则。存档将新增 `map_id` 和每图
   归一化坐标，现有照禾存档通过显式 v5 迁移。
4. **2D Navigation 只服务跟随 NPC 与敌人预警路线。** 玩家仍使用直接输入；导航
   多边形必须按角色半径内缩，因为官方导航网格只描述角色中心，且不会自动考虑
   视觉或碰撞形状。
5. **PCK 继续作为每日 clean-cache 可复现门禁，原生包作为发布门禁。** 官方导出文档确认 PCK
   只是项目数据，不是独立可执行文件；原生 macOS/Windows/Linux 发行必须安装相应
   导出模板，并分别完成签名、架构和启动测试。

## 3. 六个可独立交付的生产增量

### A. 正式像素资产合同

交付：

- 32 px TileSet 网格；56 px 人物可见高度；脚底锚点与 16×20 px 碰撞基准；
- 主角、砚青各一套四方向待机/行走动画；四类敌人各一套双帧待机、攻击与受击动画（已完成可复现语义管线）；
- 渡口地表、石路、水岸、房屋、树、药田、山门的第一套原创 TileSet；
- 源文件、导出文件、色板、命名、帧率和来源记录。

验收：替换一个角色和一块 20×12 tile 测试场；像素对齐无抖动；碰撞轮廓不随
动画帧变化；运行截图和缩放检查可复现。未通过相似性与来源审核的概念图不得直接
切片进入 Sprite Sheet。

### B. 照禾渡口生产地图

交付：

- 用 `TileMapLayer` 重建地表、道路、水体、建筑遮挡、前景和交互标记；
- 主角 `CharacterBody2D`/表现节点与 domain 探索状态之间的单向适配；
- 砚青从固定等候到跟随的寻路表现；相机边界、遮挡排序和转场淡入（均已完成首轮）；
- 现有归一化碰撞测试迁到地图数据夹具，不丢失远程交互与越界回归。

验收：旧 E2E 不改语义步骤即可通过；角色不能进入水、房屋或画面外；NPC 不穿越
建筑；1152×648 下关键目标不被 HUD 遮挡；存档 v4 能迁移到同一可玩位置。

### C. 藏泉山道可探索化

交付：

- 第二张可走地图、地图转场、预警范围、石标退路与一项可选调查；
- 三种原创普通敌人配置：岩甲兽幼体、泉苔寄壳、失衡石傀；
- 明示敌人意图、避战/撤退入口和一次性资源取舍；
- 敌方路线用 2D Navigation，战斗结算继续使用确定性 domain 数据。

验收：至少一条无战斗绕行、一条主动遭遇和一条预警后撤退路径；每条都能保存/
恢复；敌人导航与战斗状态不会因帧率不同而改变结算。

### D. 对话与人物表现

交付：

- 可复用中文对话框、说话者、纸绘头像位、逐句推进、快速显示与历史回顾；
- 砚青简报扩为 6–10 句，加入一个不改变主线但改变结算回声的回应；
- 键盘、鼠标、手柄同一 `advance_dialogue` 语义动作；
- 文本全部进入验证内容文件，头像资产单独记录来源。

验收：跳过、快速确认、存档中断与恢复不会漏发奖励或重复推进；长中文句子在
基准窗口完整换行；E2E 覆盖两种回应和结算回声。

### E. 战斗样章扩展

交付：

- 普通遭遇与岩甲兽首领共享行动解析器，不复制结算分支；
- 敌人意图、材质弱点、两种状态、砚青主动援护、石灯部署和撤退成本；
- 战斗动画只消费语义事件，不决定伤害；快速模式可跳过表现；
- 气血耗尽、撤退、胜利、读档和重复点击全部幂等。

验收：规则成功/失败/边界/畸形状态路径齐全；相同输入序列快慢模式结果一致；
战斗可用鼠标、键盘和手柄完成；结算准确记录消耗、部署与挫败。

### F. 原生候选包

交付前先由项目负责人确认首个平台。确认后才安装对应 Godot 4.7.1 官方导出模板，
添加平台 preset、图标、版本号、许可证清单和签名配置。CI 生成未签名内部候选；
签名密钥不得进入仓库。

验收：目标平台从干净机器启动、完成章节、重启续玩；包内不含 `tests/`、`tools/`
或开发文档；构建清单和 SHA-256 可追溯；中文 ICU/字体需求在目标模板中验证。

## 5. 暂不做的事情

- 不同时维护 Unity 和 Godot 客户端；
- 不在正式 TileSet 前引入 ECS、行为树或通用任务编辑器；
- 不把运行时绘图一次性删除，先作为逐图对照与回归基线；
- 不在没有授权的情况下写入外部小说人物、地名、原文或独特剧情组合；
- 不把 PCK 描述成无需 Godot runtime 的独立发行包；
- 不在平台、许可证和签名方案未确认前发布公开下载。

## 6. 尚需负责人决定

1. 首个原生候选是 macOS ARM64、Windows x86_64 还是 Linux x86_64；
2. 正式像素资产由内部绘制、签约像素画师还是经审核的混合流程完成；
3. 第一公开版本的代码、文本和资产分别采用何种许可证；
4. 15–20 分钟样章完成后，是先扩到 90 分钟，还是先做正式发行页面与试玩反馈。
