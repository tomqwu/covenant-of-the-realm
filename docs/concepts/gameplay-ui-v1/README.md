# 《山河有契》Godot 功能性美术灰盒 v1

状态：可运行、可复现的游戏镜头基线；不是正式像素资产

这一轮把[明亮美术方向 v0.2](../../design/ART_DIRECTION_v0.2.md)落实到 Godot
1152×648 实际游戏画面。所有环境、角色和敌人都是项目代码在运行时绘制的功能性
轮廓，没有把生成概念图切入游戏，也没有使用外部图片、字体或插件。

使用以下命令重新生成全部截图：

```sh
make capture-rpg-ui
```

## 角色比例

![48、56、64 px 角色比例测试](00-actor-scale-test.png)

同一轮廓分别置于亮草地、浅石路和冷影。48 px 的地图余量最好但身份信息不足；
64 px 识别最强但会压缩道路与碰撞空间；56 px 已接入第一轮自由移动与小于视觉
轮廓的碰撞盒，仍需在正式 Sprite Sheet 和镜头缩放接入后复核。

## 照禾渡口

![中文标题与继续游戏界面](01-title-screen.png)

启动先进入中文标题界面，本地存在合法版本化存档时才允许继续；键盘、鼠标和
手柄共享焦点与确认动作，存档异常会保留原文件并显示原因。

![照禾渡口功能性游戏镜头](01-zhaohe-ferry.png)

地图占据主画面，章节与状态缩到上方，地点叙事和行动收在底部暖纸面板。渡口、
河岸、道路、房屋、药田、主角和砚青可以在一个镜头中辨认。主角现在可在河岸
自由移动；河水、建筑和边界会阻挡移动，砚青、药田与山门只在靠近时显示行动。
开场简报完成后砚青才开始跟随，抬头任务依次引导交谈、采药与进山。

## 藏泉山道战斗

![藏泉山道战斗功能性游戏镜头](02-cangquan-battle.png)

岩甲兽、甲缝、符线、敌我站位、洞口和退路在明亮环境中保持可读。危险不依赖
黑暗滤镜，状态栏显示确定性战斗需要的气血、敌血、符箓与回合。

## 藏泉石室

![藏泉石室功能性游戏镜头](03-spring-chamber.png)

常规地图转入冷影洞室与分层山河，单一灵金关系引向突破目标，底部仍沿用同一套
中文行动路径。

## 第一息

![第一次引息完成画面](04-first-breath.png)

雨后暖光替代黑暗神迹，角色仍保持凡人尺度。章节结算没有增加第二套 UI 或改变
操作语义。结算明确显示境界、撤退/救援次数、符箓消耗与同伴状态，并允许回顾、
返回标题或重置后重游序章。

## 验证结论

- 56 px 是经过首轮移动与碰撞验证的角色高度工作基准，不是最终美术锁定；
- `WASD`/方向键、`E`/空格、鼠标行动和手柄 A 汇入同一语义输入路径；
- 渡口、战斗、石室和完成态具有不同构图，规则状态仍完全来自 domain 层；
- 中文地点、事件、目标、状态和行动在 1152×648 下完整显示；
- 正式生产下一步是版本化存档与标题流程，之后再替换 Sprite Sheet 与 TileSet。
